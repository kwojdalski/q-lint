# What ruff checks, and what of it means anything in q

ruff has 969 rules. This asks which of them describe a mistake a q programmer
can make, which this linter already reports, and which are worth adding.

The full list is in [ruff-rules.md](ruff-rules.md), regenerated by
`scripts/ruff_rules.py`.

## How to read a rule from another language

A rule has a mechanism and a hazard, and only the mechanism is Python's.
`B023` is about a closure not binding a loop variable - Python machinery q does
not have - but the hazard is a nested function reaching for a name from an
enclosing scope that will not be there, which is **QF005**, one of the rules
this linter reports most often.

Sorting by linter gets this wrong, because a linter groups by mechanism. Read
that way, the forty linters covering imports, annotations, async, classes,
pandas and pytest all look inapplicable. Read by hazard, a good number of them
have something to say.

Where a rule below claims a q equivalence, it was checked against q rather
than reasoned about.

## Already covered

Arrived at independently rather than ported.

| ruff | q equivalent |
|---|---|
| `W605` invalid escape sequence | **QE002** |
| `E721` type comparison | **QB013** - `type x` is a short, comparing it to a symbol is `'type` |
| `PLR0913` too many arguments | **QA001** - nine parameters is `'params` at parse, not a convention |
| `B023` closure does not bind loop variable | **QF005** - a nested lambda cannot see an enclosing local |
| `B905` `zip()` without `strict` | **QT006** - infix on two literal vectors of different lengths |
| `PLW0127` self-assignment | **QB001** - a qSQL filter comparing a column to itself |
| `DTZ005` naive `now()` | **QP003** - `.z.P` is wall clock, `.z.p` is UTC |
| `UP` deprecated constructs | **QP002** - the legacy `datetime` type |
| `EM101` string literal in exception | **QB004** - an overlong thrown message |
| `F823` local referenced before assignment | **QF014** - in q the assignment makes the name local for the whole lambda, so the read above it finds nothing |

## Worth adding

Each is a hazard q has, whatever the Python mechanism. All of them run, so all
are `style` unless noted.

**Doing by hand what a primitive does.** q's whole performance model is that
the primitive is vectorised and the loop is not, which makes this family worth
more here than in Python.

| ruff | in q | checked |
|---|---|---|
| `PERF401` manual list building | `{x+1} each til 5` for `1+til 5` | same result |
| `RUF015` single-element slice | `first asc x` for `min x` | same result |
| `C413` unnecessary call around `sorted` | `reverse asc x` for `desc x` | same result |
| `C414` nested redundant call | `distinct asc distinct x` | same result |
| `PIE807` useless lambda | `{x} each x` for `x` | same result |
| `FURB118` lambda where an operator exists | `{x+y}/[x]` for `sum x` | same result |
| `RUF017` quadratic accumulation | `,` in a loop where `raze` does it once | |

**Things left in code that should not ship.**

| ruff | in q |
|---|---|
| `T201` `print` found | `show`, `0N!` or `-1` left in a library |
| `T100` debugger trace | debugging hooks left set |
| `FIX001`-`FIX004` TODO/FIXME/XXX/HACK | the same, in q comments |
| `eradicate` commented-out code | a `/` block that is q rather than prose |

**Resources and state.**

| ruff | in q |
|---|---|
| `SIM115` open without a context manager | `hopen` with no matching `hclose` |
| `PLW0603` `global` statement | `::` assigning a global from inside a lambda |
| `PD002` `inplace=True` | in-place amend where the result is also assigned |

**Security.** Worth more attention in q than the count suggests, because q
processes commonly listen on a port and evaluate what arrives.

| ruff | in q |
|---|---|
| `S608` SQL injection by string building | a qSQL statement built by concatenation and handed to `value` |
| `S105`/`S106` hardcoded password | credentials written into a `.q` file |
| `S307` insecure eval | `value` on a string from outside the process |

**Shape and size.**

| ruff | in q |
|---|---|
| `C901`, `PLR0912` complexity | a lambda of many branches - harder to eyeball in q's density, not easier |
| `PLR0911` too many returns | several `:` exits from one lambda |
| `PLR2004` magic value | a literal threshold in a filter |
| `ARG005` unused lambda argument | `{[a;b] a+1}` |
| `F841` unused local | `{[a] b:1; a}` |
| `PLR1704` parameter reassigned | `{[a] a:2; a}` - the caller's value is gone from that point |
| `RET504` assignment used once, immediately | `r:...; :r` |

**Concurrency.** q has no `async`/`await`, but it has the hazard the
`flake8-async` rules are about: a call that blocks something which must not
block.

| ruff | in q |
|---|---|
| `ASYNC210` blocking call in async context | a synchronous IPC call (`h`) where the deferred form (`neg h`) is needed - blocking a tickerplant is the production version of this |

## Not worth adding

| ruff | why not |
|---|---|
| `E501` line too long | q is written densely on purpose; the rule would fire on idiomatic code and teach nothing |
| `E731` do not assign a lambda | assigning a lambda to a name is how q defines a function |
| `SIM108` use a ternary | `$[...]` already is one, and there is no statement form to prefer it over |
| `RET505` unnecessary `else` after return | `$[...]` has no branch to drop |
| `N803` argument naming | q has no naming convention with enough agreement to enforce; shadowing a builtin is the real hazard and **QF001** covers it |
| `PLR1714` merge comparisons | `in` exists, but the rewrite is not always equivalent under right-to-left evaluation |
| `flake8-quotes`, `flake8-commas` | one string form, no trailing-comma question |

Genuinely absent, because the construct is: imports and `__all__`, type
annotations and stubs, classes and dunder methods, decorators, f-strings,
docstring conventions, `with` statements as syntax, and everything specific to
pytest, Django, FastAPI, NumPy and Airflow.

## What the exercise says

The rules that port are, with few exceptions, `style` - they describe working q
that says one thing and means another. Almost nothing ports into `general`,
which reports what q refuses to run.

That is not because q is safer. It is because Python raises on undefined names,
wrong arity and bad types the moment a line runs, and rejects malformed source
outright, so a Python linter never needed a category for "this cannot run".
q accepts a great deal that cannot, and finds out only when something is
called. Rules for that come from q's own behaviour, and there is no borrowing
them.
