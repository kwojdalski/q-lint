# What ruff checks, and what of it means anything in q

ruff has 969 rules. This asks which of them describe a mistake a q programmer
can make, which this linter already reports, and which are worth adding.

The full list is in [ruff-rules.md](ruff-rules.md), regenerated by
`scripts/ruff_rules.py`.

## The short answer

**Almost nothing ports, and what does ports into `style` rather than
`general`.** That is not a criticism of either tool; it follows from what the
two languages leave to a linter.

Python raises on undefined names, wrong arity and bad types at the moment the
line runs, and its compiler rejects malformed source outright, so ruff spends
its rules on things that *work* and shouldn't: dead code, confusing spellings,
insecure calls, style. q does the same at runtime - but a q file is read
top to bottom at load, a lambda body is not checked until it is called, and
the language accepts a great deal that cannot possibly run. That is the gap
`--profile general` exists to fill, and ruff has almost no rules of that kind
because Python has no such gap.

Checked against q rather than assumed: every construct below that a ported
rule would report is one q accepts and runs. Not one belongs in `general`.

## By linter

| 19 of 59 | 557 | **Subject exists**, but most rules within them are still about Python spellings. The table below is what survives rule by rule. |

## Already covered

Rules this linter reports, arrived at independently rather than ported.

| ruff | q equivalent | note |
|---|---|---|
| `W605` invalid escape sequence | **QE002** | The same check; q's escape set differs. |
| `E721` type comparison | **QB013** | In q, `type x` is a short, and comparing it to a symbol is `'type`. |
| `PLR0913` too many arguments | **QA001** | q's limit is not a convention: nine parameters is `'params` at parse. |
| `PLW0127` self-assignment | **QB001** | Ours is narrower - a qSQL filter comparing a column to itself. |
| `DTZ005` naive `now()` | **QP003** | `.z.P` is wall clock, `.z.p` is UTC. `uqf` profile, being a house convention. |
| `S307` insecure eval | *deliberately absent* | `value` on a string is q's `eval`. A rule reporting every file that uses it was tried and withdrawn: it is not a defect, and at 322 findings it buried the ones that were. |

## Worth adding

Each is a real q mistake, each is `style` because q runs all of them, and each
was checked against q before being listed.

| ruff | in q | why it is worth having |
|---|---|---|
| `ARG005` unused lambda argument | `{[a;b] a+1}` | A declared parameter nothing reads is usually a call site that changed. Cheap: the scope pass already knows a lambda's parameters and what its body mentions. |
| `F841` unused local | `{[a] b:1; a}` | Same machinery, same signal. |
| `PLW0127` self-assignment | `a:a` | Always a typo, never a construct. |
| `PLR0133` two constants compared | `1=2` | A comparison whose answer is fixed is either dead or a mistyped name. |
| `PLR1704` parameter reassigned | `{[a] a:2; a}` | The parameter is gone from that point on, and the caller's value with it. |
| `C901` / `PLR0912` complexity | a lambda of many branches | q's terseness makes this harder to eyeball than in Python, not easier. |
| `PLR2004` magic value | `where px > 1000000` | Applies as anywhere else. |
| `eradicate` commented-out code | a `/` line that is q | Worth a thought: q's block comments make it easy to leave code commented for years. |

## Worth adding, but not from ruff

The gap ruff cannot help with is the one that matters most here: the
constructs q accepts and cannot run. Those come from q's own behaviour, and the
open work on them is tracked in the issue list rather than here.

## Not worth adding

| ruff | why not |
|---|---|
| `E501` line too long | q is written densely on purpose. A line limit would fire on idiomatic code and teach nothing. |
| `E731` do not assign a lambda | Assigning a lambda to a name is how q defines a function. |
| `SIM108` use a ternary | `$[...]` already is one; there is no statement form to prefer it over. |
| `RET505` unnecessary else after return | q's `:` returns from a lambda, but `$[...]` has no branch to drop. |
| `N803` argument naming | q has no naming convention with enough agreement to enforce. Shadowing a builtin is the real hazard, and **QF001** covers it. |
| `PLR1714` merge comparisons | `in` exists, but the transformation is not always equivalent under q's right-to-left evaluation. |
| `flake8-quotes`, `flake8-commas` | q has one string form and no trailing-comma question. |
